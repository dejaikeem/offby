# 야간 대규모 run — 로컬 Nemotron 3 Nano 30B, 5,569콜, 6시간 4분, $0 (2026-09-10 00:42~06:47)

목적: 120건짜리 실험이 못 보여주는 세 가지 — (1) 수천 콜 규모에서 오탐이 없나, (2) 오래 건강하게 돌던 run에 급변이 오면 몇 콜에 잡나, (3) 심판(콜마다 run 전체 재계산)이 얼마나 느려지나. Ollama `nemotron-3-nano:30b` Q4, M4 Pro 48GB, `OLLAMA_NUM_PARALLEL=4`, 클라이언트 동시성 4. 프롬프트·답변은 저장하지 않으므로 여기엔 usage 숫자만 있다.

## 설계

합성 리뷰 6,000행(`examples/gen_reviews.py --n 6000`). 잡 `overnight-30b`, 예보: 6,000콜 · 입력 40 · **출력 400**(전날 30B think-on 실측 평균 404에서) · TF nano 단가 · 예산 $5. 총 상한 6.5시간, 단계별 캡(`perl alarm` — macOS엔 GNU `timeout`이 없다).

| 단계 | 행 | 프롬프트 | thinking | 보려는 것 | 캡 |
|---|---|---|---|---|---|
| A | 0~1,999 | 기본("한 문단으로 분류") | ON | 대규모 오탐 시험 | 3h |
| B | 2,000~ | **긴**("단계별로 3문단 이상") | ON | 1,351콜 건강 뒤 급변 감지 | 1h |
| C | 2,000~5,999 | 기본 | OFF (`reasoning_effort: none`) | 완주 + 심판 판정 시간 증가 | 남은 시간 |

## 결과

| | A think-on 기본 | B think-on 긴 프롬프트 | C think-off |
|---|---|---|---|
| 콜 수 | 1,351 (3h 캡) | 217 (1h 캡) | **4,001 (완주)** |
| completion 중앙값 / 평균 | 216 / **414** | 716 / **880** | 79 / 90 |
| p95 / max | 1,359 / 4,000 | 2,168 / 4,000 | 188 / 2,690 |
| lognormal σ | 0.84 | 0.70 | 1.07 |
| `max_tokens=4000`에 잘림 | 23 (1.7%) | 1 | 0 |
| 에러 | 0 | 0 | 0 |
| 콜당 지연 중앙값 (동시성 4) | 22.9s | 63.6s | 7.0s |
| 판정 | 1.03×, **halt 없음 ✓** | **2.2×인데 halt 없음 ✗** | 0.22× ✓ |

- **A — 오탐 없음, 1,351콜.** 예보 400 vs 실측 평균 414. 4,000토큰까지 간 콜이 23개 섞여도 t = −20. 전날 규칙(평균만 비교)이었다면 초반 스파이크에 죽었을 확률이 높다.
- **B — 감지 실패.** 긴 프롬프트로 평균이 880(예보의 2.2×)이 됐는데 217콜 동안 402가 안 났다. 비율의 sd가 1.56이라 "확신 있게 2× 초과"(t > 2.5)에 도달하려면 계산상 수천 콜 창이 필요하고, 최근 30콜 창으로는 원리적으로 불가능하다. 전체 판정창은 1,351콜의 건강한 이력에 희석된다. **규칙은 명세대로 동작했지만 사용자 계약("2×까지 허용")의 문자를 어겼다** — 이 run은 예보의 2.2× 비용으로 완주했을 것. 같은 데이터에 CUSUM(S = max(0, S + min(r, 8) − 2), h = 40)을 돌리면 **168콜에서 발화**한다. 전날 시뮬 감사가 "runner-up"으로 꼽은 그 검정이 정확히 이 케이스용이었다.
- **C — 4,001콜 완주, 에러 0.** think-off는 콜당 90토큰, 7초.
- **심판 판정 시간(콜마다 run 전체 재계산, O(n))**: 500콜 0.8ms → 1,500콜 3ms → 5,569콜 **평균 3.9ms · 최대 9.4ms**. 선형. 외삽하면 20만 콜에서 콜당 ~300ms — 감사 추정(650ms)과 같은 자릿수. 1만 콜까지는 무시할 수준, 그 이상은 running-sum으로 바꿔야 한다.
- **lessons(30b)**: 5,821콜 기준 think-on 평균 471 / off 89 → 5.3× — 단, B의 긴 프롬프트가 섞여 부풀려진 값. 프롬프트가 같을 때(A vs C)는 414/90 = **4.6×**.

## 이 실험이 결정하게 만든 것

t-검정 하나로는 부족하다. 급변(≥3×)은 10~15콜에 잡고 오탐이 0이지만, **2~3×의 지속적 경미 초과**는 노이즈에 묻힌다. 후보: t-검정(급변·오탐 0) + CUSUM(누적 초과, h=40이면 2.2×를 ~170콜에)을 병행하고 402 메시지를 "sustained 2.2× over 168 calls"로 구분. 둘 다 산술이다. 결정은 README 계약("긴 답 하나로는 안 죽는다"를 유지하면서 "2×를 넘으면 잡는다"를 얼마나 문자 그대로 지킬지)의 문제.
